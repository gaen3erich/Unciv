# LLM-командующий в бою (`AiFeature.LlmCommander`)

Командующий подключается к важным боям AI-цивилизации. На каждый бой в ход идёт один вызов модели.
Код сам считает геометрию и урон и отдаёт модели меню легальных действий с последствиями.
Модель выбирает комбинацию и порядок приказов, приказы выполняются по одному с настоящими бросками.
Если что-то пошло не так, как обещало меню (приказ сорвался, юнит погиб, цель пережила «добивающую» атаку),
выполнение останавливается и модель перепланирует оставшиеся юниты, видя только то, что видел бы игрок.
Если ответ кривой или модель недоступна, бой достаётся обычному AI (UnitTactics и т.д.).

## Как устроено

| Шаг | Код | Что делает |
|---|---|---|
| Детектор боёв | `BattleDetector` | Свои и видимые вражеские юниты, свои и известные вражеские города образуют граф «достанет за ход» (движение − 1 + дальность, +1 клетка запаса). Каждая связная компонента с обеими сторонами — один бой. Свои юниты вне боёв, которые дойдут за 3 хода, становятся подкреплениями ближайшего боя. |
| Порог | `Engagement.isImportant` | Модели идут бои с 3+ юнитами (обе стороны вместе) или с нашим городом под ударом. Мелкие стычки остаются на UnitTactics. |
| Дайджест | `BattleDigestBuilder` | Для каждого своего юнита: реальные атаки этого хода (откуда, урон туда и обратно по формуле Unciv, «убивает», «мы умрём», угроза на клетке после атаки) и до 5 клеток для хода (стоять, самая безопасная, лучшая защита, сближение, прикрыть город) с бонусом защиты и ожидаемым уроном от врага. Для врагов: кого из наших они достанут на своём ходу и с каким уроном. Только то, что цивилизация видит (туман войны). |
| Промпт | `CommanderPrompt` | Системный промпт с правилами и JSON-схемой, дайджест, намерение (`intent`) с прошлого хода и итог прошлых приказов, линейка армии: что строится сейчас, что откроется через 1-2 техи, стратегические ресурсы, ближайшие города. |
| Исполнитель | `OrderExecutor` | Идёт по списку, перед каждым приказом перепроверяет легальность. Юниты, не упомянутые моделью, и юниты с сорванными приказами достаются обычному AI. |
| Перепланирование | `TacticalCommander` | При сюрпризе (приказ невыполним, наш юнит погиб, цель с пометкой KILLS выжила) выполнение останавливается, модель получает историю приказов и новый дайджест и отдаёт приказы для тех, кто ещё может действовать. По умолчанию до 2 раз за бой. Заранее исход никто не подсматривает: копия игры не используется, потому что броски в Unciv детерминированы и копия выдала бы настоящий результат. |
| Заказ войск | `production_hint` | Первый подходящий юнит из списка ставится в начало очереди названного города. |
| Память | `TacticalCommander` | `intent` и итог хода запоминаются по бою (бой узнаётся по пересечению юнитов) и кладутся в промпт следующего хода. |
| Логи | `commander-logs/` | Один `.md` на бой: промпт, ответ (и reasoning, если сервер его отдаёт), выполнение, перепланирования. Плюс `system-prompt.txt`. |

Формат ответа модели:

```json
{
  "intent": "держим холм у реки, стрелки добивают раненого мечника",
  "orders": [
    {"unit": 17, "action": "attack", "target": 42},
    {"unit": 23, "action": "attack", "target": "city@8,11", "from": "7,11"},
    {"unit": 9,  "action": "move", "tile": "7,12", "then": "fortify"},
    {"unit": 31, "action": "move_toward", "tile": "6,10"}
  ],
  "production_hint": {"city": "city@3,4", "prefer": ["Catapult", "Spearman"]}
}
```

Города называются по координатам (`city@x,y`), потому что имена в симуляциях не уникальны.

## Подключение DeepSeek через SSH-туннель

1. Поднять туннель до vLLM (порт поменять на свой):

   ```bash
   ssh -N -L 8000:localhost:8000 user@gpu-host
   ```

2. Проверить, что сервер отвечает, и узнать имя модели:

   ```bash
   curl http://localhost:8000/v1/models
   ```

3. Задать настройки через переменные окружения (или системные свойства Java `-Dunciv.commander.baseUrl=...`):

   | Переменная | По умолчанию | Смысл |
   |---|---|---|
   | `UNCIV_COMMANDER_BASE_URL` | пусто | `http://localhost:8000/v1`. Пусто — вместо модели работает заглушка (жадный план, для проверки конвейера). |
   | `UNCIV_COMMANDER_MODEL` | пусто | Имя модели из `/v1/models`. |
   | `UNCIV_COMMANDER_API_KEY` | пусто | Если vLLM запущен с `--api-key`. |
   | `UNCIV_COMMANDER_MAX_TOKENS` | 16000 | Запас на размышления R1. |
   | `UNCIV_COMMANDER_TIMEOUT_SECONDS` | 600 | Таймаут одного вызова. |
   | `UNCIV_COMMANDER_TEMPERATURE` | 0.3 | |
   | `UNCIV_COMMANDER_REPLANS` | 2 | Сколько раз за бой модель перепланирует после сюрприза. 0 — приказы просто выполняются до конца. |
   | `UNCIV_COMMANDER_MIN_UNITS` | 3 | Порог важности боя. |
   | `UNCIV_COMMANDER_MAX_CALLS` | 0 | Лимит вызовов на запуск, 0 — без лимита. После лимита бои уходят обычному AI. |
   | `UNCIV_COMMANDER_LOG_DIR` | `commander-logs` | Куда писать логи (относительно рабочей папки, у Gradle-задач это `android/assets`). |
   | `UNCIV_COMMANDER_INTENT_LANGUAGE` | Russian | Язык поля `intent`. |
   | `UNCIV_COMMANDER_REINFORCEMENT_TURNS` | 3 | Сколько ходов до боя считается подкреплением. |

   Если vLLM запущен с `--reasoning-parser deepseek_r1`, размышления приходят отдельным полем и попадают в лог под спойлер. Если нет, блок `<think>` просто вырезается из ответа.

## Запуск

### Без графики, AI против AI

```bash
export UNCIV_COMMANDER_BASE_URL=http://localhost:8000/v1
export UNCIV_COMMANDER_MODEL=deepseek-ai/DeepSeek-R1   # имя из /v1/models
export UNCIV_COMMANDER_MAX_CALLS=60

./gradlew :desktop:aiExperiment --args="--candidate=default+UnitTactics+LlmCommander --baseline=default+UnitTactics --seeds=1 --threads=1 --max-turns=200"
```

Одна дуэль на 200 ходов с войной даёт порядка 50-100 боёв для модели, при 30-120 секундах на ответ это часы,
поэтому лимит `MAX_CALLS` полезен для первых прогонов. Логи появятся в `android/assets/commander-logs/`,
отчёт — в `build/ai-experiment/report.md` (там же строки «LLM commander: ...» со счётчиками боёв, вызовов,
выполненных и сорванных приказов).

Если Gradle-демон был запущен до `export`, переменные до игры могут не дойти: добавьте `--no-daemon`.

### В обычной игре

1. Экспортировать переменные, как выше, и запустить `./gradlew desktop:run`.
2. Начать игру (можно наблюдателем) и в консоли разработчика (`` ` ``) выполнить
   `civ aiprofile Rome default+UnitTactics+LlmCommander`.
3. Во время хода этой AI-цивилизации игра ждёт ответа модели, ход идёт дольше. Логи там же, в `android/assets/commander-logs/`.

### Без модели

Без `UNCIV_COMMANDER_BASE_URL` работает заглушка `StubCommanderModel`: жадный план по тому же меню
(сначала добивания, потом лучшие размены, юниты под угрозой отходят, остальные остаются обычному AI). Она нужна, чтобы проверить весь
конвейер и посмотреть на промпты, а не чтобы хорошо играть.

## Что смотреть в логах

- **Промпт**: читаемо ли меню, нет ли бессмысленных вариантов, хватает ли модели информации.
- **intent**: разумен ли замысел, держится ли он от хода к ходу.
- **Перепланирование**: как модель реагирует на сюрприз, меняет ли замысел или держится его.
- **FAIL** в выполнении: какие приказы срываются. Большинство срывов при правильном меню — когда два юнита
  хотят встать на одну клетку для атаки; после такого срыва модель перепланирует.
